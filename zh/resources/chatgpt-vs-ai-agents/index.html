ChatGPT 和 AI agent：你的业务任务到底需要哪个？

需要有人来提问、把关、拍板时，用 chatbot。只有当任务要跨好几个步骤或工具、而且权限能控制得足够窄时，才考虑用 agent。

核心要点
  • ChatGPT 这类 chatbot 是针对一个请求生成一段回应；AI agent 能围绕一个目标跨多个步骤、调用连接好的工具，有时还会直接采取行动。
  • 多数团队应该先从 chat 用起，接着把工作流写成文档，只有在价值和审核流程都清楚之后，才把 agent 的权限授予出去。
  • 规则固定、输入结构化的活，普通自动化比两者都可靠：除非内容本身需要理解，否则用不着 AI。
  • 给 agent 授权之前先回答五个问题：它能做什么动作、能看到什么、哪里要批准、出错怎么发现、动作怎么撤回。

实际的区别

ChatGPT 和 AI agent 该用哪个，几乎每场培训都有人问，问法通常是「这个活要不要上 agent？」。简短的回答：ChatGPT 这类 chatbot，是针对一个请求生成一段回应；AI agent 则能围绕一个目标跨越多个步骤，调用连接好的工具，有时还会直接采取行动。

chatbot 待在一场对话里。你提供信息，要它给出结果，你审核，再决定下一步怎么走。agent 则能沿着一串环节运转：读取被批准的输入，判断下一步该做什么，调用某个工具，产出结果，再把结果发到别的地方去。

这份额外的能力能省下不少活，但也把出错的面积放大了。要问的不是哪种技术听起来更先进，而是这个任务到底需要多大的自主权。

当结果需要判断时，用 chat

刚开始上手时，chat 往往是对的选择。它让人离工作很近，也让审核这一步看得见。几个不错的例子：

  • 把批准过的笔记整理成一份会议纪要草稿
  • 对比两份文档，列出差异供人审核
  • 把一条给客户的消息改写得语气更清楚
  • 从一小批文本里抽取出分类
  • 为一次会议或面试拟出问题

每个例子里，都还是由人来提供背景、检查结果、决定用不用。我们的企业 AI 培训多半也是从这里开始：学员带一项自己本来就在做的任务，用 chat 做一遍，把审核那一步写下来。

当工作要跨步骤或跨工具时，再考虑 agent

当任务是重复的、下一步要依赖上一步里发现的信息、而且在不同工具之间来回也是这份工作里要紧的一环时，agent 才可能派上用场。

举个例子，一个「邮件转待办」的工作流，也许会挑出符合既定规则的邮件，抽取出建议的动作，生成一条待办草稿，再放进一个待审核的队列里。这个 agent 不该悄悄地把每封邮件都当成待办，也不该在没经过批准时就替你发出承诺。

别忽略了普通的自动化

有些活既用不上 chatbot，也用不上 agent。如果规则是固定的、输入又是结构化的，普通的自动化往往更可靠。「有人提交表单，就发一封确认邮件、再加一行记录」，只要内容本身不需要去理解，这就用不着 AI。

最简单又可靠的系统，通常就是最好的系统：

  • 条件已知时，用固定规则。
  • 有人需要帮忙产出或理解信息时，用 chat。
  • 只有当工作确实需要灵活的步骤或工具时，才用 agent。

在给 agent 授权之前，先问五个问题

  1. 它到底能做哪些动作？只读权限，和能发送、删除、购买、发布，是两码事。
  2. 它能看到哪些信息？把数据来源限制在这个工作流真正需要的范围内。AI 数据边界一页纸就是这段对话的精简版。
  3. 哪些动作需要批准？界定清楚 agent 必须停下来、交给人来定夺的那个节点。
  4. 出了错怎么发现？留好日志、抽查样本，并指定一个负责人。
  5. 动作要怎么撤回？在自动化开始之前，就把补救方案想好。

agent 不适合的情况

没人能把任务拆成步骤、输入每周都换一副模样、或者一次错误动作的代价很高又没人有时间审核，这几种情况下，agent 都是错的工具。还有一种：团队还没在同一个任务上用过 chat。没有这段经验，人分不清 agent 的产出是好是坏，审核那一步就会悄无声息地失效。

遇到这些情况，先留在 chat 加一份写好的清单上。等这个任务用 AI 辅助的手动方式做过几周、出错的方式都摸清了，再回头考虑 agent。

我们在培训里怎么讲这层区别

培训时，把同一个任务画成三种做法：固定规则、chat 交互、agent 工作流。学员对比一下各自的投入、风险、权限和审核。厂商自己的指南用工程语言说的也是同一件事：Anthropic 的 Building effective agents 建议先用最简单、可组合的模式，只有在自主性能带来可衡量的好处时才加上去。这能帮他们挑到合适的工具，而不是把每个任务都当成上 agent 的机会。

给非技术团队的 AI 培训课程围绕这个练习给出了完整的工作坊结构。

接下来 14 天可以做的事

  • 挑一个重复性任务，写下它的输入、输出和由谁检查。用 chat 做三遍。
  • 记下每一处你不得不离开聊天窗口、去别处查东西或搬运结果的环节。这份清单，就是「要不要 agent」这个问题的诚实答案。
  • 在接入任何工具之前，把上面五个问题填好，答案和工作流放在一起。

常见问题

ChatGPT 算不算 AI agent？

不算。ChatGPT 是 chatbot：针对眼前这个请求生成一段回应。agent 是能规划多个步骤、调用工具、朝着目标行动的系统。有些产品把 chatbot 包上了 agent 功能，所以要看工具实际能做什么，而不是看它叫什么。

小公司该先用 ChatGPT 还是先上 AI agent？

先用 chat。它让人离工作很近，也让审核这一步看得见。接着把工作流写成文档。只有当任务是重复的、要跨工具、而且有人负责审核和补救方案时，才给 agent 授权。

AI agent 应该拿到什么权限？

能完成任务的最小权限。只读权限，和能发送、删除、购买、发布，差别很大。界定清楚 agent 必须停下来问人的那个节点，留好日志，错误才找得到。

什么时候普通自动化比 AI 更好？

规则固定、输入结构化的时候。「有人提交表单，就发一封确认邮件、再加一行记录」用不着 AI。只有内容本身需要理解时，才用 chat 或 agent。
