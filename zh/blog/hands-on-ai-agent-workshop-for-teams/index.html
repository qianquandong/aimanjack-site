团队 AI agent 实操工作坊，现场到底做什么

想办 agent 工作坊的团队，多半希望散场时手里有个能跑的东西，而不是听一场关于未来的演讲。下面一步步讲清这堂课该包含什么，以及容易在哪里出问题。

核心要点
  • 团队 AI agent 实操工作坊结束时，每个团队都应拥有一个能用的 agent：建在公司已批准的 AI 工具里（例如 ChatGPT 或 Claude），并在团队每周重复的任务上测试过。
  • AI agent 是会调用工具、循环执行来完成一项工作的模型，不是产品标签。对多数办公室团队来说，第一个 agent 就是一个保存好的助手：有书面指令、经批准的参考资料和明确的输出格式。
  • 数据规则先于搭建：哪些工具已获批准、哪些信息不能输入、agent 的输出在使用或发出前由谁签字。
  • 练习使用模拟或脱敏材料。工作坊里做的 agent 负责起草和核对，不发邮件、不改记录、不接入在用的业务系统。
  • 课程以每个 agent 的决定收尾：保留、调整还是停止，以及由谁负责。

团队说要办 agent 工作坊时，想要的是什么

这类需求通常很具体。管理者手里有一张清单，列着团队希望交给 AI agent 的活，比如准备会议简报、分拣进来的问题、追踪资产在哪里；他想要的是一堂让大家亲手做出第一个 agent 的课，而不是抽象地听 agent 有多厉害。团队 AI agent 实操工作坊有用的样子就是这样：散场时，团队带走一个在自己工作上能跑的 agent。

这套做法先在社区活动里验证过。2026 年 4 月 18 日的达拉斯 AI 黑客松上，37 位参与者分组，在一个约三小时的下午里动手做项目，最后向全场演示。5 月 17 日的 agent 主题聚会上，我们讲了 agent 到底是什么，以及多个角色清楚的 agent 怎样分工完成一项复杂任务。企业工作坊沿用同一条规矩：课上做出真东西，再拿出来给大家看。

Agent、工作流、聊天：真正要分清的区别

这类课上的困惑，多半来自“agent”这个词。Jack 在 Agent 101 笔记里的定义是：agent 是会调用工具、循环执行来完成一项工作的模型，不是一个产品标签。值得分清三个层次：

  • 聊天：一个人打一句请求，看一个回答。什么都没保存，下周又从零开始。
  • 工作流：一套写下来的步骤，输入和输出都明确，团队里谁都能重跑、能核对。
  • Agent：保存在工具里的工作流，带着自己的指令、经批准的参考资料，以及工具允许时可调用的能力，比如搜索或读文件。在 ChatGPT 里通常是自定义 GPT 或项目，在 Claude 里是 Project。

对非技术团队来说，第一个 agent 应该是第三层，但要建在第二层之上。如果团队连工作流都写不下来，agent 每次的表现也不会一样。

课程怎么进行

我们的 90 分钟团队 AI 工作坊，无论目标是一条工作流还是第一个 agent，都按同样的顺序走：

  1. 先定数据规则。确定哪些 AI 工具已获批准、哪些信息不能输入、哪些输出必须由人签字后才能使用。有了 agent，这一步更重要，因为它每次都会照同一套指令执行。
  2. 挑选这份工作。每个人列出每周重复的任务，按四个标准打分：频率够不够高、输入输出是否清楚、能否快速核验、能否在不涉及敏感信息的情况下练习。得分最高的那项，就是 agent 的工作。
  3. 把指令写成规格说明。提示词是规格说明，不是咒语。给 agent 写清它的角色、会收到什么输入、必须返回什么格式、绝不能做什么，以及一条一分钟内就能检查的验收标准。
  4. 在已批准的工具里搭建。把指令和经批准的参考资料保存在公司已经在用的工具里，然后用模拟或脱敏的样例材料实际跑一遍。
  5. 故意把它弄坏。至少准备一个刻意设置问题的测试用例：缺一个字段、前后矛盾、或者超出 agent 职责的请求。看 agent 怎么处理，团队就知道东西发出去之前该检查什么。
  6. 决定下一步。这个 agent 是保留、调整还是停止，由谁负责，两周后怎么回查。

如果团队带来一长串想做的 agent，处理方法一样：给清单打分，课上先做最强的一两个，其余的写成规格说明，课后再搭。

团队 agent 的数据安全

工作坊里做的 agent 负责起草、分拣和核对。培训期间，它不应该发邮件、更新客户记录或接入在用的业务系统。这些动作需要人来批准，往往还需要 IT 对系统对接做决定。我们的工作坊是 AI 培训，不是 CRM、ERP 或自动化开发，所以 agent 处理的是这些系统之外的那部分工作：整理记录、汇总更新、核对导出的数据。

agent 分享给全团队之前，先写下三个答案：它放在哪个工具里、哪些信息绝不能给它、它的输出由谁签字。免费的 AI 数据边界一页纸可以作为起点。

什么时候这套做法不灵

没有已批准的工具，就不灵。如果大家只能在个人账号里搭 agent，这堂课等于教他们继续把公司的活放在个人账号里。先批准一款工具；AI 工具审批清单就是为这个决定准备的。

工作说不清楚，也不灵。“一个帮我们做市场的 agent”没法测试；“一个把已批准的活动记录整理成我们格式的五点回顾的 agent”可以。

如果你真正需要的是软件，这也不是合适的课。agent 要自己在你的系统里读写记录，那是和 IT 一起做的实施项目，不是培训工作坊。

接下来 14 天能做的

  • 列出团队想交给 agent 的活，每项按频率、输入输出是否清楚、核验快不快、能否不用敏感数据练习来打分。
  • 写下三个答案：已批准的工具、不能输入的信息、由谁签字。
  • 挑出得分最高的那项，准备两三份脱敏后的输入样例和一份合格的输出样例。

常见问题

什么是团队 AI agent 实操工作坊？

一次实时课程，团队在自己的工作上搭建并测试第一个 AI agent。先定数据规则，挑一项重复任务，把 agent 的指令写成规格说明，在公司已批准的 AI 工具里搭好，用模拟或脱敏材料测试，最后决定保留、调整还是停止。

做 AI agent 需要开发人员吗？

不需要。对多数办公室团队来说，第一个 agent 就是公司已在用的工具里保存好的助手，例如 ChatGPT 的自定义 GPT 或 Claude 的 Project，配上书面指令和经批准的参考资料，不用写代码。

AI agent 和 AI 工作流有什么区别？

工作流是一套写下来的步骤，输入输出明确，谁都能重跑。agent 是会调用工具、循环执行来完成一项工作的模型，落到实际，就是保存在 AI 工具里、带着自己指令和资料的工作流。工作流写不下来的团队，做出的 agent 每次表现都不一样。

agent 工作坊里用公司数据安全吗？

练习应使用模拟或脱敏材料，并且只用公司已批准的 AI 工具。工作坊期间，客户个人信息、密码和保密文件一律不输入任何工具；没有人签字，agent 也不应发出消息或修改记录。

工作坊多长时间、怎么收费？

目前有三种形式：90 分钟团队工作坊、全天上门培训，以及 4 节 × 90 分钟课程。每种形式都按需报价。人数、地点和准备工作量在书面报价中确认。
